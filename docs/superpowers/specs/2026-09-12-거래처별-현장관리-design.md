# 거래처별 현장관리 앱 — 설계문서

**작성일:** 2026-09-12
**상태:** 사용자 승인 대기
**저장 위치:** `D:\n8n_거래처별_현장관리`

## 1. 목적

WeNote(안드로이드 메모앱)로 거래처별 현장 메모를 관리하던 방식을 대체하는 **개인용 모바일 웹앱(PWA)**.
WeNote의 문제는 "자유 메모라 정리가 안 됨" — 주소/일정/비번/필름넘버 같은 정보를 **칸으로 구조화**하고,
그 칸을 골라서 **업자에게 질문** 또는 **팀원에게 공유** 문구로 바로 복사하는 것이 핵심.

- 사용자: 대표 본인 1명, 폰에서만 사용
- 팀원/업자에게는 앱이 아니라 **복사한 텍스트**(카톡/문자)로 전달
- 데이터는 폰(localStorage)에 즉시 저장, n8n → Airtable로 조용히 백업. 새 폰에서 자동 복원

### 2.4 질문/공유 복사 동작
- 상세 화면 진입 시 체크박스 자동 세팅:
  - **비어있는 항목** → 체크됨 (질문 대상). 단 name/memo는 질문 대상 아님
  - **채워진 항목** → 체크됨 (공유 대상)
  - 사용자가 수동으로 체크 해제/추가 가능
- [업자에게 질문 복사]: 체크된 항목 중 **비어있는 것**의 질문 문구를 모아 복사

### 2.5 고정값 (거래처별, 접이식)
- 담당자: [{이름, 전화}] 여러 명, 각 행에 [전화] 버튼(`tel:`)
- 사진(명함·단가표 등): 여러 장, 썸네일 격자. 탭하면 **전체 화면 뷰어**(`#photo/<id>` — 폰 뒤로가기로 닫힘),
  사진을 탭하면 원본 크기로 스크롤 확대(단가표 숫자 확인용), 상단에서 설명 편집·삭제
  - [＋ 사진 추가] → 폰 카메라/앨범 선택(`<input type="file" accept="image/*" multiple>`)
  - 올린 직후 **설명(메모) 입력창**을 띄운다 (예: "영림 2026년 단가"). 파일명은 쓰지 않음 — `1000020841` 같은 이름은 찾는 데 도움이 안 됨
  - 저장 전 자동 축소 — **해상도 우선**(단가표 숫자가 읽혀야 함):
    긴 변 2000px부터 0.8배씩 1000px까지, 각 크기에서 품질 0.85→0.45, **600KB 이하**면 채택
    (실측: A4 단가표 사진 1500×2000 ≈ 290KB, 명함 ≈ 40KB)
  - 썸네일 별도 생성(긴 변 400px, 40KB 이하) — 목록 격자와 상태(localStorage)·백업 메타 행에 사용
  - 원본은 **IndexedDB**(`sitenote`/`photos`)에 저장. 상태 JSON 에는 넣지 않는다
    (입력할 때마다 수백 KB 를 직렬화하면 느려지고 localStorage 5MB 도 금방 참)
  - localStorage 가 가득 차면 방금 올린 사진을 되돌리고 "저장공간이 가득 찼습니다" 안내
- 업체 필름단가 / 업체 인건비단가 / 견적시 주의사항 / 현장 주의사항: 각각 여러 줄 텍스트
- 메인 화면 탭 아래에 접힌 상태로 표시, 펼치면 바로 편집

## 3. 데이터 구조 (localStorage, JSON)

```js
{
  version: 1,
  clients: [ { id, name, order, contacts: [{name, phone}], filmPrice, laborPrice, quoteNote, siteNote, updatedAt } ],
  photos:  [ { id, clientId, name, thumb: 'data:image/jpeg;base64,…', w, h, bytes, parts, createdAt, updatedAt } ],
           // 원본은 IndexedDB sitenote/photos[id]. 구버전 사진은 dataUrl 을 그대로 들고 있고 그대로 동작한다
  sites:   [ { id, clientId, color, createdAt, updatedAt,
               name, unit, size, address, date, pwLobby, pwUnit, gate,
               carReg: {v: '필요'|'불필요'|'미확인', memo},
               parking,
               cargoEv: {v: '사용'|'일반사용'|'미확인', memo},
               toilet, films: [{place, code}], memo } ],
  settings: { questions: {unit: '…', …}, backupKey, lastTab },
  syncQueue: [ {op: 'upsert'|'delete', type: 'client'|'site'|'photo'|'settings', id, data, ts} ]
}
```
- id: `c_` / `s_` / `p_` + 시각+난수 (문자열)
- color: 8색 팔레트 인덱스 0~7. 새 현장 = (해당 거래처 현장 수) mod 8
- localStorage 키: `sitenote.v1`

## 4. 백업/복원 (n8n + Airtable)

### 4.1 Airtable 베이스 `거래처별 현장관리`
- 테이블 `거래처`: `id`(기본 필드, 텍스트), `이름`, `순서`, `data`(롱텍스트 JSON), `updatedAt`
- 테이블 `현장`: `id`, `현장명`, `거래처id`, `시작날짜`, `data`(롱텍스트 JSON), `updatedAt`
- 테이블 `사진`: `id`, `이름`, `거래처id`, `data`(롱텍스트 JSON), `수정시각`, `삭제`
  - 사진 1장 = **메타 행 1개**(`p_xxx` — 이름·크기·thumb·조각수) + **조각 행 N개**(`p_xxx#0`, `#1`, … — 원본 base64 를 9만자씩)
  - 롱텍스트 한 칸이 10만자라 큰 사진은 나눠 담는다. 복원 시 앱이 `photoId`/`i` 로 다시 붙여 IndexedDB 에 넣음
  - 300KB 짜리 단가표 ≈ 5행. Airtable 행 수 한도(무료 플랜 1,000행)를 쓰는 속도에 유의
- 테이블 `설정`: `id`(고정 `settings`), `data`
- 행 단위로 저장하는 이유: 롱텍스트 10만자 한도 회피, Airtable에서 직접 읽기 가능

### 4.2 n8n 워크플로우 `거래처별 현장관리 백업` (기존 Railway 인스턴스)
- `POST /webhook/sitenote-sync` — body `{key, ops: [{op, type, id, data}]}`
  - key 검증 (n8n 환경변수/워크플로우 내 상수와 비교, 틀리면 401)
  - op별: upsert → id로 검색 후 update 또는 create, delete → id로 검색 후 삭제
  - 응답 `{ok: true, done: n}`
- `GET /webhook/sitenote-restore?key=…` — 전체 `{clients, sites, photos, settings}` 반환
- 워크플로우 JSON은 `n8n/현장관리_백업.json`에 보관, 배포는 `n8n-deploy` 스킬 사용

### 4.3 앱 동작
- 저장 → localStorage 즉시 반영 → syncQueue에 op 추가(같은 id는 마지막 것으로 합침) → 3초 디바운스 후 전송
- 사진 조각 op 는 큐에 본문 없이 `{photoRef, part}` 참조만 쌓고, 전송 직전에 IndexedDB 원본에서 잘라 채운다
  (백업 전까지 폰 저장소에 수백 KB 사본이 쌓이지 않도록)
- 오프라인/실패 시 큐 유지, 온라인 복귀(`online` 이벤트) 또는 앱 열 때 재시도
- 상단에 "⚠ 백업 대기 N건" 표시 (0건이면 숨김). 백업키 없으면 "백업키 설정 필요"
- 자동 복원: 앱 열 때 localStorage가 비어있고 백업키가 있을 때만 restore 호출. (새 폰은 백업키를 먼저 설정 화면에서 입력해야 하므로, 실제로는 "백업키 저장 직후 데이터가 비어있으면 복원" 흐름)
- 수동 복원: 설정에서 2단계 확인 후 전체 덮어쓰기

## 5. 기술/배포

- 순수 HTML/JS/CSS, 빌드 없음 (품질관리·1분견적 앱과 동일 방식)
- 파일: `index.html`, `app.js`, `store.js`, `share.js`, `style.css`, `manifest.json`, `sw.js`, `icon-*.png`, `n8n/`, `test/`, `docs/`
- PWA: 홈화면 추가, sw.js는 앱 파일만 캐시(네트워크 우선), `?v=YYYYMMDD` 캐시버스팅
- 배포: GitHub Pages (새 repo, 예 `jayunsu22/sitenote`). Netlify 미사용(크레딧)
- **push는 사용자가 지시할 때만.** 로컬에서 여러 수정 → 한 번에 push
