# 현장 연결: 일정 앱 현장 ↔ 현장업무(관리자 앱) 한 번에 만들고 이어 붙이기

2026-10-05 · 승인된 방향: "일정 앱(거래처별 현장관리)의 현장을 본체로 두고, 현장업무는 거기서 한 번에 만들어 연결한다"

## 문제

같은 현장이 서로 이어지지 않은 곳에 따로 있다.

| 어디 | 키 | 저장 |
|---|---|---|
| 일정 앱(sitenote) 현장 | `s_xxxx` | 폰 localStorage 가 원본, Airtable "거래처별 현장관리" 는 백업 |
| 관리자 앱 현장업무 | `rec...` (현장목록) | Airtable "블로그자동화" |
| 견적(quote_pro) | 견적코드 | 현장관리_현장ID(=일정 앱 id)만 저장, 관리자 앱으로 보낸 기록은 폰 저장함에만 |

일정 앱 현장과 관리자 앱 현장을 이어주는 값이 어디에도 없어서, 현장명·날짜를 두 번 입력하고 견적을 보낼 때마다 새 현장업무가 만들어진다.

## 두 가지 업무 순서 (확인됨)

- 1번 (견적 먼저): 거래처 등록 → 방문견적 발행 → 현장업무로 보내기 → 시공 → 정산견적
- 2번 (견적 없이): 거래처 등록 → 일정 앱에서 현장 만들기 → 현장업무 시작 → 시공 → 정산견적(관리자 앱 현장 카드에서만 열린다)

두 순서 모두 "일정 앱 현장 1개 = 현장업무 1개" 로 끝나야 한다.

## 제약 (설계를 정한 이유)

- 일정 앱의 원본은 폰 안 데이터다. 서버 백업은 폰 → 서버 한 방향이라, 다른 앱이 서버 쪽에 연결 값을 적어도 폰의 다음 백업이 덮어쓴다. **연결 값은 일정 앱이 자기 현장에 적는다.**
- 기존 n8n 워크플로우는 수정하지 않는다. 쓰는 요청은 이미 있는 것뿐이다:
  - `film-quality-save` 의 `create_project` (현장업무 만들기), `update_project_name` (이름·시공일 바꾸기)
  - `update_workers` (기사 명단 교체), `film-quality-get-v2?code=` GET (현장업무 상세: 명단·배정)
  - `film-admin-get-v2` GET (현장업무 목록)
  - `sitenote-restore` GET (견적 앱이 일정 앱 현장을 읽는 길)
- 일정 앱(github.io)에서 위 두 웹훅을 부르는 것은 CORS 로 허용됨을 확인했다 (2026-10-05).

## 설계

### 1. 데이터: 현장에 `adminId` 한 칸

일정 앱 현장 객체에 `adminId` (관리자 앱 현장 `rec...`, 없으면 빈 문자열)와 `adminSynced` (`{ name, date, staff }`, 마지막으로 관리자 앱에 맞춘 값)를 둔다. 현장 객체 전체가 백업되므로 서버 변경이 필요 없다. 필드가 없는 기존 현장은 지금처럼 동작한다.

### 2. 일정 앱: 현장 화면 머리의 "현장업무" 버튼 (`#siteHead`)

- 연결 전: `🛠 현장업무 연결` → 바텀시트
  - **새로 만들기**: 현장명(= 현장 제목), 시공일(= 1일차 날짜, 없으면 빈 값), 인원(= 날짜별 인원의 합집합, 쉼표)으로 `create_project` 를 보내고, 응답 id 를 `adminId` 에 저장. 응답에 id 가 없으면 목록을 다시 받아 방금 만든 이름으로 찾는다(견적 앱과 같은 방식). 만드는 도중 두 번 눌려도 현장업무가 두 개 생기지 않게 버튼을 잠근다.
  - **기존 현장업무에서 고르기**: 현장업무 목록(보관함 제외)을 받아, 아직 어느 일정 앱 현장에도 안 묶인 것을 위에, 현장명이 비슷한 것을 더 위에 둔다(견적 앱의 `QuoteToSite.현장정렬` 과 같은 조각 비교 규칙을 공용으로 쓴다). 이미 다른 현장에 묶인 것은 회색으로 표시하고 고를 수 없다. 이미 두 곳에 따로 만들어 둔 현장을 한 번씩 묶는 길이다.
- 연결 후: `🛠 현장업무 열기` (관리자 앱의 그 현장으로 이동) + 더보기에 `연결 해제`. 해제해도 관리자 앱 현장은 지우지 않는다.

### 3. 일정 앱 → 현장업무 자동 맞춤 (한 방향)

연결된 현장의 **현장명 또는 1일차 날짜가 `adminSynced` 와 달라졌을 때만** `update_project_name`(`newName`/`newDate`)을 보낸다. 성공하면 `adminSynced` 를 갱신한다. 실패하거나 오프라인이면 `adminSynced` 를 그대로 두어 다음 변경·앱 실행 때 다시 시도한다(백업 큐와 같은 정신, 별도 큐는 만들지 않는다). 관리자 앱에서 직접 고친 값은, 일정 앱의 같은 칸이 바뀌기 전에는 덮어쓰지 않는다.

### 3-1. 인원도 함께 관리 (2026-10-05 추가)

일정 앱은 **날짜별 인원**(`days[].staff`), 관리자 앱은 **현장 기사 명단**(현장업무에 배정할 후보, `workers`)과 **품목별 배정**(`밑작업기사`/`시공기사`)을 가진다. 겹치는 것은 "누가 이 현장에 오나"이므로, **일정 앱의 인원이 기준**이고 관리자 앱의 기사 명단이 따라간다. 품목별 배정은 관리자 앱에서만 한다(일정 앱은 건드리지 않는다).

- 기준 명단 = 일정 앱 모든 날의 인원을 합친 이름 목록(처음 나온 순서).
- 맞추는 방법(관리자 앱 `update_workers` 는 명단 **전체를 교체**하므로, 보내기 직전에 `film-quality-get-v2?code=<adminId>` 로 현재 명단과 배정을 새로 받아 계산한다):
  - **추가**: 기준 명단에 있고 관리자 앱 명단에 없는 이름은 관리자 명단 **뒤에** 붙인다. 관리자 앱의 기존 순서와 이름은 유지한다.
  - **삭제**: "지난번에 우리가 맞춰 넣은 이름(`adminSynced.staff`)인데 이제 기준 명단에 없는 이름"만 대상으로, **그 기사에게 배정된 품목이 하나도 없을 때만** 관리자 명단에서 뺀다. 배정이 있으면 남겨 두고 시트에 "배정이 있어 남겨둠: ○○"로 알린다. 배정을 자동으로 풀지는 않는다.
  - 관리자 앱에서 직접 넣은 기사(일당 등)는 건드리지 않는다. 시트에 "관리자 앱에만 있는 기사: ○○"로 보여주기만 한다.
- 맞춤 시점: 인원을 고친 뒤 3초 뒤(백업과 같은 디바운스), 연결 직후, 앱을 열 때 `adminSynced.staff` 와 기준 명단이 다르면 한 번 더. 성공하면 `adminSynced.staff` 를 갱신한다.
- 한계: 가져오기와 교체 사이(약 1~2초)에 관리자 앱에서 같은 현장의 기사를 동시에 바꾸면 그 변경이 지워질 수 있다. 사장님 혼자 쓰는 앱이라 허용하고, 보내기 직전에 새로 받는 것으로 창을 줄인다.
- 이름 바꾸기: 일정 앱에서 이름을 고치면 "새 이름 추가 + (배정 없으면) 옛 이름 삭제"로 처리된다. 옛 이름에 배정이 있으면 남는다(위 규칙).
- 시트에 인원 맞춤 상태(`맞춤 완료` / `대기` / 실패 이유)와 `지금 맞추기` 버튼을 둔다.

이번에 하지 않는 것: 주소(일정 앱에 주소 칸이 없다), 관리자 앱 → 일정 앱 방향의 인원 가져오기(날짜 정보가 없어 칸에 넣을 수 없다).

### 4. 관리자 앱: 주인용 딥링크 `admin.html#site=<rec id>`

기존 `?code=` 링크는 현장소장용(잠금 화면 없이 그 현장만 보이는 제한 보기)이라 주인이 쓰면 안 된다. 암호 확인이 끝난 뒤 `#site=` 가 있으면 그 현장 상세를 연다. 암호 화면을 건너뛰지 않는다.

### 5. 견적 앱: 보내기가 연결된 현장업무를 쓴다

- 업체·현장을 고른 견적(`state.현장연결`)이고 그 일정 앱 현장에 `adminId` 가 있으면, "현장으로 보내기" 는 새 현장업무를 만들지 않고 그 `adminId` 로 바로 품목·사진을 보낸다. (견적 앱의 업체 캐시가 일정 앱 현장의 `adminId` 도 함께 읽는다. 보내기를 누를 때 캐시가 오래됐으면 먼저 한 번 갱신한다.)
- 일정 앱 현장은 있는데 아직 `adminId` 가 없으면: 지금처럼 새 현장업무를 만든 뒤, 완료 화면에 `일정 앱에서 연결 완료` 버튼을 띄운다. 누르면 `일정 앱/#adminlink=<일정 앱 현장 id>:<rec id>` 로 이동하고, 일정 앱이 열릴 때 해시를 읽어 그 현장의 `adminId` 에 적고 해시를 지운다. 현장이 폰에 없거나 이미 다른 값이 있으면 덮어쓰지 않고 알려만 준다.
- 일정 앱 현장을 고르지 않은 견적은 지금과 같다.

### 6. 오류 처리

- 웹훅 실패: 화면에 이유를 보여주고 `adminId` 는 적지 않는다(반쪽 상태 금지). 새로 만들기는 성공 응답을 받은 뒤에만 id 를 저장한다.
- 목록을 못 받으면 "새로 만들기"만 쓸 수 있게 한다.
- 연결된 현장업무가 관리자 앱에서 보관/삭제돼 목록에서 사라져도 일정 앱은 아무것도 지우지 않는다. 열기 버튼은 관리자 앱이 "현장을 찾을 수 없음"을 알려준다.

### 7. 테스트

- 순수 로직(조각 비교 정렬, 이미 묶인 것 제외, 이름·날짜 맞춤 필요 여부 판정, 인원 명단 계산(추가·배정 있으면 삭제 보류·관리자 전용 기사 보존), `#adminlink` 파싱)은 node 테스트로 먼저 쓴다 (`test/` 의 기존 방식).
- 화면은 로컬 서버에서 모바일 크기로 확인한다. 웹훅은 실제 현장업무를 만드는 요청이므로 테스트로 만든 현장업무는 보관함 처리하고 보고한다(삭제하지 않는다).
