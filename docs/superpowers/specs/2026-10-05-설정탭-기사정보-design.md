# 설정 화면 탭 나누기 + 기사 정보 칸 추가 (설계 + 계획)

2026-10-05 · 사용자 확정: 시안 A(위쪽 색 탭), 기사 정보는 모두 글자로 저장, 위치는 지금 그대로(설정 → 팀원 명단)
실행: 같은 세션 인라인. 범위가 작아 설계와 계획을 한 문서로 쓴다.

## 문제

1. 설정 화면이 8개 항목을 한 줄로 길게 늘어놓아 찾기 어렵다.
2. 기사 정보는 이름·연락처·차량번호뿐이다. 경력·페이·사는곳·메모를 적을 곳이 없다.

## 설계

### 1. 설정 탭 (일정 앱 `index.html`/`app.js`/`style.css`)

현장 화면의 탭(`.site-tabs`/`.site-tab`)과 같은 모양의 5칸 색 탭을 설정 화면 맨 위(상단바 바로 아래)에 둔다.

| 탭 | 색(기존 클래스) | 들어가는 항목 |
|---|---|---|
| 팀원 | `tab-info` 파랑 | 팀원 명단 |
| 현장준비 | `tab-staff` 초록 | 부자재 기본 항목, AS 부자재·공구 |
| 후기 | `tab-film` 보라 | 후기 질문, 현장 태그 |
| 문구 | `tab-supply` 주황 | 업자에게 질문 문구 |
| 백업 | `tab-gray` 회색(신규) | 백업(Airtable), 정보 |

- 각 `.settings-section` 에 `data-stab="team|prep|review|text|backup"` 를 달고, 탭을 고르면 그 탭 항목만 보인다. 항목은 DOM 에 계속 있어서 기존 렌더·이벤트 코드는 그대로 돈다.
- 설정을 열 때마다 첫 탭(팀원)으로 시작한다. 탭을 바꾸면 맨 위로 스크롤한다.
- 서버·백업 변경 없음.

### 2. 기사 정보 (`settings.people[이름]`)

- 필드: `phone`(전화번호) · `car`(차량번호) · `career`(경력) · `pay`(페이) · `home`(사는곳) · `memo`(메모). 모두 글자(적는 대로). 이름은 키라서 이 창에서는 읽기 전용이다.
- 설정 팀원 명단의 각 줄은 `이름 + 전화·차량 한 줄 요약 + ›` 로 줄이고, 누르면 "기사 정보" 창에서 6칸을 적는다(적는 대로 저장). 요약에 연락처가 없으면 "연락처 없음".
- 인원 선택창의 전화·차량 빠른 입력은 그대로 둔다. 단, **이 입력이 새 칸을 지우지 않도록** 저장을 "합치기"로 바꾼다(지금은 `{phone, car}` 로 통째로 교체해서 경력·페이가 날아간다).
- 저장 위치는 기존 `settings.people` 라서 기존 백업·복원이 그대로 실어 나른다. `normalizePeople` 이 새 칸을 버리지 않게 고친다.
- **페이·경력·사는곳·메모는 카톡 복사 문구(업자에게 연락처 보내기, 관리실 차량등록, AS 방문·차량)에 절대 나가지 않는다.** 그 문구 함수들은 `phone`/`car` 만 읽는다. 테스트로 고정한다.
- 보안 메모: 페이 같은 정보가 백업(Airtable "설정" 표)과 복원 응답에 들어간다. 이미 백업키로 보호되는 곳이다.
