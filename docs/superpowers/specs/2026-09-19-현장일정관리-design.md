# 현장일정관리 (sitenote 확장) — 설계문서

**작성일:** 2026-09-19
**상태:** 사용자 승인 (2026-09-19 대화에서 화면 목업까지 확인)
**대상:** `D:\n8n_거래처별_현장관리` (sitenote PWA). 별도 앱이 아니라 **기존 앱에 붙이는 기능**
**목업:** `2026-09-19-현장일정관리-mockup.html` (같은 폴더, 브라우저로 열면 폰 3장)

## 1. 목적

현장이 여러 개일 때 "내일 어느 현장에 누가 가고, 필름은 준비됐고, 본드·장갑은 챙겼나"를
매일 저녁 한 화면에서 확인하고 체크하기 위한 기능. sitenote 의 현장 카드와 **같은 현장**을 쓴다.

현장마다 추적하는 것 세 가지 (전부 ☑ 수준, 중간 단계 없음):

| 항목 | 형태 | 결정 근거 |
|---|---|---|
| 필름 준비 | 필름/시공위치 줄마다 `준비됨 ☑` | 발주·입고 단계는 머릿속으로 관리 (사용자 선택 D) |
| 인원 배치 | 날짜마다 이름 목록 (팀원 명단에서 탭 + 즉석 입력) | 날짜별·현장별 이름이 보이면 됨 (선택 C) |
| 부자재 | 현장마다 체크리스트 (기본 항목은 설정에서) | 수량·재고 없음 (선택 A) |

한눈에 보는 화면은 **주간 목록 + 오늘·내일 펼침** (선택 C).

## 2. 화면

### 2.1 새 화면 `#schedule` — "📅 일정"

```
← 거래처            📅 일정                      ⚙
──────────────────────────────────────────────
[오늘] 9/19 (금)
┌ 군포 우륵아파트 704동 606호          A인테리어 ┐   ← 카드 색 = 현장 색
│ 👤 [김기사] [박기사] [＋]                     │   ← 칩 탭 = 빼기, ＋ = 인원 선택창
│ 🎞 ☑ 현관문 뒷면 PS035  ☐ 붙박이장 W211       │   ← 탭하면 그 자리에서 토글
│ 🧰 ☑ 본드  ☐ 장갑                            │
└─────────────────────────────────────────────┘
[내일] 9/20 (토)
┌ … 펼침 … ┐
9/21 (일)
 ▌수원 영통 래미안   👤박기사 · 🎞 0/4 · 🧰 0/2  ●    ← 접힘. 탭하면 펼침 (토글)
9/22 (월)  현장 없음
… 오늘부터 14일까지 날짜 전부 표시 …
▸ 이후 일정 3건 (9/26 ~ 10/2)                          ← 탭하면 같은 형식으로 이어서 펼침
```

- **진입:** 메인 상단바에 📅 버튼. 일정 화면의 ← 는 메인으로. `settings.lastView` 에 마지막 화면
  (`main` | `schedule`)을 기억해 앱을 다시 열면 그 화면으로 시작
- **범위:** 오늘 ~ 오늘+13일은 현장이 없어도 날짜 줄을 찍는다("현장 없음"). 그 이후는
  "이후 일정 N건" 한 줄로 접고, 탭하면 날짜 있는 것만 이어서 보여준다. 어제 이전은 안 보인다.
  시작날짜가 없는 현장은 이 화면에 나오지 않는다 (거래처 탭에서는 그대로)
- **하루 = 현장의 `days[]` 한 줄.** 한 현장이 9/19, 9/20 두 줄이면 두 날짜 모두에 나온다.
  제목 옆에 `2일차` 처럼 일차 표시 (days 가 1줄이면 표시 안 함)
- **펼침 카드:** 현장색 배경. 세 줄(👤/🎞/🧰). 필름·부자재 줄이 비어 있으면 그 줄은 `🎞 (없음)` 으로 표시.
  카드 제목 탭 → `#site/<id>` (기존 현장 상세)
- **접힌 줄:** 왼쪽 굵은 선 = 현장색. `👤이름들 · 🎞 준비/전체 · 🧰 준비/전체` 와 점 하나:
  빨강 = 미준비 항목이 하나라도 있음 **또는** 인원 0명, 초록 = 필름·부자재 전부 ☑ 이고 인원 ≥1
- **겹침 경고:** 같은 날짜에 같은 이름(공백 제거, 대소문자 그대로)이 두 현장 이상에 있으면
  그 칩을 빨간 배경 + `⚠` 로 표시. 경고일 뿐 막지는 않는다 (오전/오후 나눠 가는 경우가 있음)
- **체크·인원 변경은 즉시 저장** (기존 현장 상세와 같은 `Store.updateSite` 경로 → 백업 큐)

### 2.2 현장 상세 `#site/<id>` — 붙는 부분

1. **필름/시공위치** 각 줄 맨 앞에 ☑ (`films[i].ready`). 줄 추가 시 `ready:false`
2. **새 구역 "일정·인원"** (필름 구역 아래, 현장사진 위)
   ```
   일정·인원
   1일차 9/19   [김기사] [박기사] [＋]
   2일차 9/20   [김기사] [＋]              ✕
   [＋ 날 추가]
   ```
   - 1일차 날짜 = 시작날짜 칸(`date`)과 **항상 같은 값**. 시작날짜를 바꾸면 `days[0].date` 도 바뀌고,
     나머지 일차는 **같은 일수만큼 밀린다** (9/19,9/20 → 시작을 9/22 로 바꾸면 9/22,9/23)
   - 시작날짜를 지우면 `days` 는 유지하되 일정 화면에서 빠진다 (날짜 없는 현장)
   - `＋ 날 추가` → 마지막 일차 +1일. 각 일차의 날짜는 탭해서 달력으로 바꿀 수 있다 (1일차 제외 — 1일차는 시작날짜 칸에서)
   - 2일차 이후는 ✕ 로 삭제. 1일차는 삭제 불가
   - `＋` → **인원 선택창**(바텀시트): 설정의 팀원 명단이 칩으로, 이미 들어간 사람은 강조. 탭하면 넣기/빼기.
     아래 입력칸에 이름을 치고 확인하면 즉석 인력으로 추가 (명단에는 안 들어감).
     즉석 인력도 칩 모양은 같다
3. **새 구역 "부자재"** (일정·인원 아래)
   ```
   부자재
   ☑ 본드   ✕
   ☐ 장갑   ✕
   [＋ 항목 추가]
   ```
   - 새 현장을 만들 때 `settings.supplyDefaults` 를 복사해서 깔아준다 (`ready:false`)
   - 항목 추가는 이름 입력 → 줄 추가. ✕ 로 삭제

### 2.3 설정 — 두 목록 추가

- **팀원 명단** `settings.team: string[]` — 추가(이름 입력)/삭제/순서는 추가 순
- **부자재 기본 항목** `settings.supplyDefaults: string[]` — 초기값 `['본드','장갑']`. 바꿔도 이미 만든 현장에는 영향 없음
- 둘 다 백업 대상 (`settingsForSync` 에 포함)

## 3. 데이터

```js
// site (기존 필드에 추가)
site.films    = [{ loc:'현관문 뒷면', film:'PS035', ready:false }, …]   // ready 추가
site.days     = [{ date:'2026-09-19', staff:['김기사','박기사'] }, …]   // days[0].date === site.date
site.supplies = [{ name:'본드', ready:false }, …]

// settings (기존 questions/backupKey/lastTab 에 추가)
settings.team           = ['김기사','박기사']
settings.supplyDefaults = ['본드','장갑']
settings.lastView       = 'main' | 'schedule'
```

- 이름은 **문자열**로 저장 (ID 아님). 명단에서 지워도 과거 현장 기록은 그대로. 즉석 인력과 구분 없음
- **기존 데이터 보정** (`normalizeSite`, 앱 열 때 + 복원 시):
  - `films[i].ready` 없으면 `false`
  - `days` 없으면 `[{ date: site.date || '', staff: [] }]`
  - `supplies` 없으면 `settings.supplyDefaults` 로 채움 (설정이 아직 없으면 `['본드','장갑']`)
- `days[0].date` 와 `site.date` 가 어긋난 데이터(백업 복원 등)는 `normalizeSite` 가 `site.date` 를 기준으로 맞춘다
- 백업: 현장은 JSON 통째로 Airtable 한 행에 들어가므로 **n8n 워크플로우·Airtable 스키마 변경 없음**.
  설정 행에 `team`, `supplyDefaults` 키가 추가될 뿐 (같은 JSON 칸)

## 4. 공유 문구

- **팀원에게 공유**: 시작날짜 줄 다음에 인원 줄을 넣는다. days 가 1줄이면 `👤 김기사·박기사`,
  여러 줄이면 `👤 9/19 김기사·박기사 / 9/20 김기사`. 인원이 전부 비어 있으면 줄 자체를 뺀다
- 준비 체크(필름 ☑, 부자재)는 공유·질문 문구에 **넣지 않는다** (내부용)
- `Share.FIELDS` 순서는 바꾸지 않는다 (기존 테스트·문구 의존). 인원 줄은 FIELDS 항목이 아니라
  `buildShare` 가 `date` 줄 뒤에 끼워 넣는다

## 6. 오류·경계 처리

- 인원 선택창에서 빈 문자열·공백만 입력 → 무시. 이미 있는 이름 입력 → 중복 추가 안 함
- 같은 현장 안에서 같은 날짜가 두 줄이면(사용자가 날짜를 겹치게 고침) 두 줄 다 그 날짜에 표시하되 합치지 않는다.
  겹침 경고는 **현장이 다를 때만**
- `date` 가 잘못된 형식이면 (수동 입력 등) 일정 화면에서 제외
- localStorage 저장·백업 실패 처리는 기존 경로 그대로 (토스트)

## 7. 1차에서 일부러 뺀 것 (YAGNI)

- 필름 수량(m/장), 발주·입고 단계
- 부자재 수량·재고 차감·주문 알림
- 월간 달력, 팀원별 보기, 일정 화면에서 현장 새로 만들기
- 겹침을 막는 제약, 알림/푸시
- 팀원 명단에 전화번호 등 부가 정보 (거래처 담당자와 별개)
