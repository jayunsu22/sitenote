# 현장일정관리 (sitenote 확장) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**실행자:** 같은 세션 인라인 (writing-plans-extras: 계약·테스트 케이스·검증 명령 수준. 코드는 파일에 직접 쓴다)
**스펙:** `docs/superpowers/specs/2026-09-19-현장일정관리-design.md` · 목업 `…-mockup.html`

**Goal:** sitenote 현장에 필름 준비 ☑ / 날짜별 인원 / 부자재 체크리스트를 붙이고, 오늘·내일이 펼쳐진 주간 "📅 일정" 화면에서 한눈에 보고 체크한다.

**Architecture:** 순수 함수(날짜 묶기·겹침·준비 카운트·공유 줄)는 `share.js`, 상태 보정·저장은 `store.js`, 화면은 `app.js`. 기존 패턴(`Share.FIELDS` 순서 고정, `Store.updateSite` 즉시 저장 → 백업 큐, 해시 라우팅) 그대로. n8n/Airtable 변경 없음.

**Tech Stack:** vanilla HTML/JS/CSS (빌드 없음), `node test/*.test.js`, preview `sitenote`(python http.server 5195, launch.json 은 `D:\n8n_1분견적(필름)\.claude\launch.json`)

## Global Constraints

- `Share.FIELDS` 배열 순서·키를 바꾸지 않는다 (기존 테스트 42건 + 공유 문구 의존)
- films 줄 객체는 `{ place, code }` + 새로 `ready` (스펙의 loc/film 아님)
- 날짜는 전부 `YYYY-MM-DD` 문자열, 로컬 시간. "오늘"은 `new Date()` 로컬 날짜
- 이름은 문자열 저장, ID 없음. 겹침 비교는 공백 제거 후 같은 문자열
- JS/CSS 를 바꾼 뒤 `index.html` 의 `?v=YYYYMMDD` 와 `sw.js` 의 `CACHE` 를 갱신 (한 번, 마지막 태스크에서)
- 커밋은 태스크마다 로컬로. **푸시는 사용자가 말할 때만**
- 기존 코드의 주석 밀도·한국어 주석·`function` 선언식·`var` 스타일을 따른다

### Task 1: share.js 순수 함수 (날짜 묶기 · 겹침 · 준비 카운트 · 공유 줄 · 날짜 밀기)

**Interfaces:**
- Consumes: `str()`, `shortDate(iso)` (기존, `share.js:92,137`), `titleLine`
- Produces (전부 `Share.` 로 export):
  - `addDays(iso, n) → iso` — `'2026-09-19', 1 → '2026-09-20'`. 잘못된 iso 면 `''`
  - `isIsoDate(v) → bool` — `/^\d{4}-\d{2}-\d{2}$/` 이고 실제 날짜
  - `todayIso(now?) → iso` — 로컬 날짜 (테스트용 `now` 주입)
  - `shiftDays(days, newStart) → days` — `days[0].date` 를 `newStart` 로 두고 나머지를 같은 일수만큼 밀어 **새 배열** 반환. days 가 비었으면 `[{date:newStart, staff:[]}]`. newStart 가 `''` 면 `days[0].date=''` 만 바꾸고 나머지 유지
  - `groupByDate(sites, from, count) → { days: [{date, entries:[{site, dayIndex, dayCount}]}], later: [{date, entries}] , laterCount }`
    - `from` 부터 `count` 일은 현장이 없어도 줄이 있다. `later` 는 그 이후 날짜만(있는 것만, 오름차순). `laterCount` = later 의 entries 총합
    - `from` 이전 날짜의 days 줄은 버린다. `isIsoDate` 가 아닌 날짜 줄도 버린다
    - entries 정렬: 같은 날 안에서는 site.createdAt 오름차순 (안정)
    - `dayIndex` 는 0-base, `dayCount = site.days.length`
  - `findOverlaps(sites) → { [date]: { [normName]: n } }` — 같은 날짜, **서로 다른 현장** 에 나온 이름 수. n ≥ 2 만 남긴다. normName = 공백 제거
  - `readyCount(site) → { films:[ready, total], supplies:[ready, total] }` — films 는 `code` 가 빈 줄 제외
  - `isReady(site) → bool` — films·supplies 전부 ready 이고 (total 0 이면 그 항목은 통과), `days` 중 staff 가 하나라도 있음 → true
  - `staffLine(site) → string` — 1일 `👤 김기사·박기사`, 여러 날 `👤 9/19 김기사·박기사 / 9/20 김기사` (staff 가 빈 날은 건너뛴다). 전부 비면 `''`
  - `buildShare` 변경: `has.date` 줄(head) 바로 다음에 `staffLine(site)` 이 비어있지 않으면 삽입
