# 할 일 (일정 화면 통합) Implementation Plan

> **실행자: 같은 세션이 곧바로 인라인 실행** (superpowers:executing-plans). 그래서 이 계획은 파일 맵·인터페이스·테스트 케이스·검증 명령만 적고, 코드는 파일에 바로 쓴다.

**Goal:** 일정 앱(sitenote) 일정 화면에 할 일을 날짜별로 섞어 보여주고, 할 일을 거래처(메모 내역)·현장(필름 주문·인원)·AS(부자재)와 이어 붙인다. 자동 할 일 3종 포함.

**Architecture:** 순수 계산(자동 할 일, 날짜 묶기)은 `share.js`, 상태·백업 큐는 `store.js`, 화면은 `app.js`/`style.css`. 할 일은 `state.tasks[]` 로 새 백업 타입 `task`, 거래처 메모 내역은 `client.notes[]`(거래처 객체 안). 백업은 n8n "거래처별 현장관리 백업" 워크플로우에 '할일' 표 추가.

**Tech Stack:** 바닐라 JS(ES5 스타일, IIFE), node 테스트(`node test/*.test.js`), GitHub Pages, n8n + Airtable.

설계: `docs/superpowers/specs/2026-10-14-할일-design.md`

## Global Constraints

- 코드 스타일: 기존과 같은 ES5 `var`/`function`, 한국어 주석, 화면 문구는 쉬운 우리말.
- 기존 데이터 깨지지 않기: 없는 칸은 normalize 에서 기본값. 옛 서버 복원 응답에 `tasks` 가 없으면 폰 할 일 유지.
- 181노드 워크플로우 `LGaXbJ6ESCOqYTg9` 는 건드리지 않는다.
- 푸시(GitHub Pages 배포)·n8n 라이브 반영 전 사용자 확인.
- 배포 시 캐시 버전(`index.html` 의 `?v=`, `sw.js` CACHE) 올림.

### Task 1: share.js — 자동 할 일·날짜 묶기 (순수 함수)

**Files:** Modify `share.js`, Test `test/share.test.js`

**Interfaces — Produces:**
- `DEFAULT_TASK_RULES = { filmDays: 3, staffDays: 3, supplyDays: 1 }`
- `normalizeTaskRules(raw) → {filmDays, staffDays, supplyDays}` (0~14 정수, 이상하면 기본값)
- `autoTasks(sites, today, rules) → Task[]` — 각 항목 `{ id:'auto:film|staff|supply:<siteId>[:<svcId>]', auto:true, kind:'film'|'staff'|'supply', title, date: today, time:'', link:{type:'site'|'service', id, siteId, label}, done:false }`
  - film: 첫날 ≥ today, dayDiff(today, 첫날) ≤ filmDays, filmStageOf < 2 → `필름 주문: <현장명>`
  - staff: 같은 창, staffStatus.short > 0 → `인원 모집: <현장명> (N명 부족)`
  - supply: 현장 첫날까지 ≤ supplyDays 이고 supplies 중 ready=false 있음 → `부자재 준비: <현장명>`; AS(done=false, date ≥ today, ≤ supplyDays) tools 중 toolsReady 에 없는 것 있음 → `AS 부자재: <현장명>` (link.type='service')
- `taskTimeKey(t) → string` 정렬 키: 'HH:MM' → '1HH:MM', '오전' → '2', '오후' → '3', '' → '4' (시각 있는 것 → 오전 → 오후 → 없음)
- `taskGroups(tasks, today) → { overdue: Task[], undated: Task[], byDate: { iso: { open: Task[], done: Task[] } } }` — overdue = date < today && !done (날짜순); undated = date '' && !done; 지난 날짜의 done 도 byDate 에 들어간다. 각 open 은 taskTimeKey 순.

**테스트 케이스:** film 3일 전 뜸 / 4일 전 안 뜸 / 당일 뜸 / 첫날 지나면 안 뜸 / stage 2 이상 안 뜸; staff 부족·충분·need 0; supply 전날 뜸·2일 전 안 뜸·전부 ready 안 뜸; AS tools 일부 체크·전부 체크·done AS; rules 바꾸면 경계 이동; taskGroups 밀림·날짜없음·시간 정렬('09:00' < '13:00' < 오전 < 오후 < 없음)·done 분리.

- [ ] 테스트 먼저 → `node test/share.test.js` 실패 확인 → 구현 → 통과 → 커밋

### Task 2: store.js — 할 일·메모 내역·설정·복원

**Files:** Modify `store.js`, Test `test/store.test.js`

**Interfaces — Consumes:** Task 1 (`Share.normalizeTaskRules`, `Share.DEFAULT_TASK_RULES`).
**Produces (Store 에 공개):**
- `tasks() → Task[]` (createdAt 순), `getTask(id)`
- `addTask({title, date, time, link}) → Task` (빈 title 이면 null), `updateTask(id, patch)`, `deleteTask(id)` — 큐 op `type:'task'`
- `completeTask(id, result) → Task` — done=true, doneAt, result 저장; link.type==='client' 이고 result 있으면 `addClientNote(clientId, {text: result, kind, taskId})`; `uncompleteTask(id)` (메모 내역은 그대로)
- `markFilmOrdered(siteId)` — filmStage 를 max(현재, 2)
- `addClientNote(clientId, {text, kind?, taskId?, date?}) → note` (맨 앞에 넣기, date 기본 오늘), `updateClientNote(clientId, noteId, text)`, `deleteClientNote(clientId, noteId)`
- `setServiceToolReady(siteId, svcId, name, ready)` — service.toolsReady 갱신
- 설정 `taskRules` — defaultSettings·SYNCED_SETTINGS·settingsForSync·restore 에 추가
- `normalizeClient` 에 `notes: []` 정리, `normalizeServices` 에 `toolsReady`(tools 에 있는 이름만), `normalizeTask`
- `load`/`restore`: `state.tasks`; restore 응답에 `tasks` 배열 없으면 폰 것 유지
- 기존 `deleteClient`/`deleteSite` 는 할 일을 지우지 않는다 (label 로 남음)

**테스트 케이스:** add/update/delete 큐 op; completeTask 거래처 → notes[0] 에 결과·taskId, 결과 빈칸이면 메모 안 생김; uncomplete 후 notes 유지; markFilmOrdered 0→2, 3→3; 옛 거래처 notes 없음 → []; 옛 AS toolsReady 없음 → []; toolsReady 에 tools 에 없는 이름 버림; restore 에 tasks 있음/없음; taskRules 동기화 키.

- [ ] 테스트 먼저 → `node test/store.test.js` 실패 → 구현 → 통과(기존 테스트 포함) → 커밋

### Task 3: 일정 화면에 할 일 섞기 (app.js·style.css)

**Files:** Modify `app.js` (`renderScheduleList`, `calCell`/`renderScheduleCal`), `style.css`, `index.html`(＋ 할 일 떠 있는 버튼)

**Interfaces — Consumes:** `Share.autoTasks`, `Share.taskGroups`, `Store.tasks`, `Store.completeTask`, `Store.state.settings.taskRules`. **Produces:** `renderTaskRow(t) → Element`, `renderTaskDay(iso, group) → Element`, `openTaskDetail(t)` 호출(Task 4 에서 구현; 이 태스크에선 임시로 없으면 무시하지 않고 Task 4 와 같이 커밋해도 됨).

- 맨 위: 고른 날짜 바 → 밀린 할 일 상자(빨강) → 날짜 없음 상자(접힘) → AS 대기 → 지난 일정 → 오늘부터
- 오늘 묶음엔 자동 할 일 + 오늘 할 일. 날짜 묶음은 그날 런/AS 카드 앞(시작일과 같은 날) 또는 날짜순 사이.

- 달력 칸 주황 점(할 일 있는 날, 안 끝난 것만).
