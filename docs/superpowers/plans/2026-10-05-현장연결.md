# 현장 연결 (일정 앱 현장 ↔ 현장업무) 구현 계획

> **실행자: 같은 세션이 인라인 실행** (executing-plans). 코드는 파일에 바로 쓰고, 이 계획은 파일 맵·인터페이스·테스트 케이스·검증 명령만 담는다.
> 설계: `docs/superpowers/specs/2026-10-05-현장연결-design.md`

**Goal:** 일정 앱 현장 1개 = 관리자 앱 현장업무 1개로 연결하고(`adminId`), 현장명·시공일·인원을 일정 앱 기준으로 자동 맞춘다. 견적 앱은 연결된 현장업무로 바로 보낸다.

**Architecture:** 연결 값은 일정 앱 현장 객체(`adminId`, `adminSynced`)에만 저장(폰 원본, 기존 백업이 그대로 실어 나름). 새 로직은 UMD 파일 `adminlink.js`(순수 함수 + fetch 주입형 네트워크 함수)에 모아 node 로 테스트하고, `app.js` 는 화면·트리거만 맡는다. n8n 은 건드리지 않고 기존 웹훅만 쓴다.

**Tech Stack:** 바닐라 JS(UMD, 빌드 없음), `node test/x.test.js` 커스텀 러너(`console.log('N passed, M failed'); process.exit(fail?1:0)`), n8n 웹훅(기존), Airtable(기존).

## Global Constraints

- 기존 n8n 워크플로우는 수정·삭제하지 않는다. 쓰는 요청은 `film-quality-save` 의 `create_project` / `update_project_name`(`newName`,`newDate`) / `update_workers`(`workersText`=쉼표 구분 전체 목록, **전체 교체**), `film-quality-get-v2?code=<rec id>`(응답 `workers: string[]`, `tasks[].fields.밑작업기사/시공기사`), `film-admin-get-v2`(응답 `projects[]{id, fields{현장명, 시공일자, 시공기사, 보관함, createdTime}}`), `toggle_project_archive`(테스트 정리용)뿐이다. CORS 는 `https://jayunsu22.github.io` 에서 허용됨을 확인했다.
- 연결 값은 반드시 일정 앱이 자기 현장에 적는다(서버 백업은 폰 → 서버 한 방향).
- 인원 맞춤: 추가는 관리자 명단 뒤에, 삭제는 "지난번에 우리가 넣은 이름이면서 이제 기준 명단에 없고 배정 품목이 0개일 때만", 배정은 절대 자동으로 풀지 않는다, 관리자 앱에만 있는 기사는 건드리지 않는다.
- 데이터를 삭제하지 않는다. 테스트로 만든 현장업무는 보관함 처리한다.
- 커밋은 로컬만. **푸시는 사용자가 "푸시해"라고 할 때만**, 푸시 전 `git fetch` 로 원격 변경 확인.
- 커밋 메시지는 한국어 + `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- 줄바꿈: `admin.js`·`admin.html`·`admin_style.css` 는 CRLF 다. 통째로 다시 쓰지 말고 Edit 로 고치거나 CRLF 를 보존한다(`git diff --stat` 이 수십 줄이어야 정상).
- 캐시 버전: 일정 앱은 `index.html` 의 `?v=` 와 `sw.js` 의 `CACHE`/`FILES` 를 같이 올린다(현재 `20261005c` → `20261005d`). 관리자 앱은 `admin.html` 의 `admin_style.css?v=`·`admin.js?v=` 를 같이 올린다(현재 `20261003f` → `20261005a`), 앱 헤더 배지(`v…`)로 보고한다.
- 화면 확인은 로컬 서버(`sitenote-static` 5195, `admin-static` 8843, `songil-static` 8080)에서 모바일 크기로 한다.

### Task 2: 네트워크 함수 + `syncSite` + 저장소 기본값 (일정 앱)

**Files:** Modify `adminlink.js`, `test/adminlink.test.js`, `store.js`(`blankSite`), `test/store.test.js`

**Interfaces:**
- Consumes: Task 1 의 모든 함수. `deps = { fetchFn, Store }` — `Store.getSite(id)`, `Store.updateSite(id, patch)` (실제 `store.js` 의 공개 API)
- Produces:
  - `URLS = { save, list, detail }` (각각 `…/webhook/film-quality-save`, `film-admin-get-v2`, `film-quality-get-v2`)
  - `createProject(siteId, deps)` → `Promise<string adminId>`. 이미 `adminId` 가 있으면 새로 만들지 않고 그 값을 돌려준다. 같은 `siteId` 로 진행 중인 호출이 있으면 그 Promise 를 재사용한다(이중 생성 방지). 응답에서 `id`(`d.id || d.fields.id`, 배열이면 첫 원소)를 못 찾으면 목록을 새로 받아 같은 이름 중 `createdTime` 이 가장 새 것을 쓰고, 그래도 없으면 reject. **id 를 얻은 뒤에만** `Store.updateSite(siteId, { adminId, adminSynced:{ name, date, staff } })` 로 저장(만들 때 보낸 값이 곧 맞춘 값).
  - `listProjects(deps)` → `Promise<[{ id, name, date, workers: string[] }]>`, `보관함` 이 true 인 것 제외, `시공기사` 문자열은 `,` 로 쪼개 공백 제거
  - `linkExisting(siteId, adminId, deps)` → `adminId` 를 저장하고 `adminSynced = { name: adminTitle(site), date: '', staff: [] }` 로 둔다. 이름은 "맞춘 것"으로 기록해 **관리자 앱의 기존 현장명을 덮어쓰지 않고**(일정 앱 이름이 다른 모양일 수 있다), 날짜·인원은 첫 맞춤 대상으로 남겨 `syncSite` 가 처음 맞춘다(구현 중 결정, 2026-10-05)
  - `unlink(siteId, deps)` → `adminId:''`, `adminSynced:null`
  - `syncSite(siteId, deps)` → `Promise<{ ok, meta, staff, kept, adminOnly, error }>`. 동작: `needsSync` 가 any 가 아니면 `{ok:true}` 즉시. name/date 가 필요하면 `update_project_name` 에 바뀐 키(`newName`/`newDate`)만 보내고 성공하면 `adminSynced.name/date` 갱신. staff 가 필요하면 `detail?code=` 를 새로 받아 `current=workers`, `assigned=tasks 의 밑작업기사·시공기사 이름들`, `planRoster` 로 계산해 `next` 가 `current` 와 다를 때만 `update_workers`(`workersText = next.join(',')`) 를 보내고, 성공하면 `adminSynced.staff = rosterOf(site)`. 각 단계는 독립: 한 단계 실패가 다른 단계의 기록을 막지 않는다. 실패한 단계는 `adminSynced` 를 그대로 둔다. `kept`/`adminOnly` 는 시트 안내용으로 돌려준다.
  - 같은 `siteId` 로 `syncSite` 가 겹쳐 실행되지 않게 한다(진행 중이면 그 Promise 를 반환).
