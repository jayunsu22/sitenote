# 거래처별 현장관리 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WeNote를 대체하는 개인용 모바일 PWA — 거래처 탭별 현장 카드, 14개 구조화 항목, 업자 질문/팀원 공유 복사, localStorage 저장 + n8n/Airtable 백업.

**Architecture:** 빌드 없는 순수 HTML/JS/CSS 단일 페이지 앱. `share.js`(순수 함수: 문구 생성·정렬·색상·빈값 판정)와 `store.js`(localStorage + 동기화 큐)는 화면과 분리되어 node에서 테스트. `app.js`는 화면 전환·렌더·이벤트만 담당. 백업은 n8n webhook 2개 + Airtable 테이블 3개.

**Tech Stack:** Vanilla JS (ES2020, 모듈 없이 전역 IIFE — 기존 앱들과 동일), node `assert` 테스트, n8n(Railway), Airtable, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-12-거래처별-현장관리-design.md`

## Global Constraints

- 파일: `index.html`, `app.js`, `store.js`, `share.js`, `style.css`, `manifest.json`, `sw.js`, `icon-*.png`, `n8n/`, `test/`
- localStorage 키: `sitenote.v1`
- 캐시버스팅: HTML에서 JS/CSS를 `?v=YYYYMMDD`로 로드, JS/CSS 수정 시 갱신
- 현장 항목 14개 키(순서): `name, unit, size, address, date, pwLobby, pwUnit, gate, carReg, parking, cargoEv, toilet, films, memo`
- 선택형 값: carReg `필요|불필요|미확인`, cargoEv `사용|일반사용|미확인`; 기본 `미확인`
- 색상 팔레트 8개 인덱스 0~7, 새 현장 색 = (거래처 내 현장 수) mod 8
- push는 사용자 지시 시에만. 로컬 커밋은 태스크마다
- 소스에 비밀키 없음 (백업키는 settings.backupKey)

### Task 1: share.js — 항목 정의·빈값 판정·문구 생성 (TDD)

**Files:** Create `share.js`, `test/share.test.js`

**Produces:**
```js
Share.FIELDS   // [{key, label, type:'text'|'date'|'select'|'films'|'multiline', question, options?}]
Share.DEFAULT_QUESTIONS // {key: question} (name, memo 제외)
Share.isEmpty(site, key) -> boolean
Share.titleLine(site) -> "현장명 동호수 평형" (빈 것 생략)
Share.buildQuestion(site, keys, questions) -> string  // "[제목]\n- 질문\n- 질문"
Share.buildShare(site, keys) -> string
Share.sortSites(sites) -> sites (날짜 없음 우선, 그 다음 날짜 오름차순, 동률은 createdAt 내림차순)
Share.nextColor(sites, clientId) -> 0..7
Share.mergeQueue(queue, op) -> queue (같은 type+id는 마지막으로 교체; delete는 이전 upsert 제거 후 추가)
```

### Task 2: store.js — 상태·CRUD·큐 (TDD, localStorage 모킹)

**Files:** Create `store.js`, `test/store.test.js`

**Produces:**
```js
Store.load() / Store.state
Store.addClient(name) -> client ; Store.renameClient(id,name) ; Store.deleteClient(id) (현장도 삭제) ; Store.reorderClients(idsInOrder) ; Store.updateClient(id, patch)
Store.addSite(clientId) -> site (색상 자동, 14개 항목 기본값) ; Store.updateSite(id, patch) ; Store.deleteSite(id)
Store.sitesOf(clientId) -> 정렬된 배열
Store.setSettings(patch)
Store.pendingCount() ; Store.flush() (fetch POST) ; Store.restore() (fetch GET → 전체 교체)
Store.onChange(fn)
```
- 모든 변경: state 갱신 → localStorage 저장 → syncQueue mergeQueue → 3초 디바운스 flush → onChange 호출
- flush: backupKey 없거나 큐 비면 no-op. 실패 시 큐 유지. `navigator.onLine`이 false면 skip, `online` 이벤트에서 재시도
- restore: 상태가 비어있거나 force일 때만

- [ ] Step 1: 테스트 작성 (global.localStorage 메모리 모킹, fetch 모킹) — addClient/order, deleteClient cascades, addSite color, updateSite queue merge, flush 성공 시 큐 비움 / 실패 시 유지 / key 없으면 미호출
- [ ] Step 2: 실패 확인 → Step 3: 구현 → Step 4: 통과 → Step 5: commit `feat: store.js 상태·큐·동기화`
